Navigation and shell

How a resident moves through the town, and how the shell frames everything else. The bar names the place, the bottom nav names the five things you can do, and every surface between them is a variation on one idea: say where you are, then get out of the way.

Three bars, one set of class names, zero markup differences. The only thing that changed is a data-town attribute on an ancestor, which reassigns values behind the same token names. That is the seam the whole platform is built on: a resident in Helena gets their own town, and a creation someone shipped in Russellville styled with var(--ts-navy) comes along intact. If any of these three needed a component change, the second town would fork the first and the third would never happen.

Five destinations, and the fifth is the argument. Creations sits in the nav as a peer, not under a More menu, because the thesis is that value compounds with builders. A platform that hides the thing residents made has already decided it is a news app. Everything else a builder needs lives off the You tab and the command palette, so the resident path stays five words wide.

Safe area and target size The home indicator is not a design element you can borrow. Padding, not margin, so the fill runs to the glass.

The obvious move at this width is a dashboard of cards, and it is the wrong one: a dashboard implies everything is equally urgent, which is exactly the Nextdoor feeling we are avoiding. The test is what the column is for, not how much room the window happens to have.

The host header is the seam a resident can feel. It is the one header set on navy, it names the neighbour who built the thing, and it says out loud what the sandbox can see. A creation that looked exactly like the rest of the app would be more elegant and much worse: the whole trust model depends on a resident knowing when they have stepped into something a neighbour wrote. The close control is a cross, not a chevron, because you are leaving rather than going back.

Tabs, segmented control, chip rail Three shapes for three jobs: peer views, one view filtered, and a list too long to fit.
Underline tabs — peer views, each a different set of things

Underline plus aria-selected plus a weight change. Counts sit in the tab because "128 articles" is a reason to press it.

Segmented control — one view, filtered

A pill, never an underline. Underline means "you are somewhere else now"; a pill means "the same list, fewer of them".

Chip rail — the long category list, scrollable

The rail bleeds to the right edge and a fade sits over the last 32px, which is the only honest way to say "there is more". A chip that ends flush with the margin reads as the end of the list.

Back, and where a breadcrumb earns its place Back is a history. A breadcrumb is a claim about structure, and most screens do not have one.
A story — back only

The label names where you will land, not the word "Back". A resident who arrived from a shared link gets "Today" here too, because that is where the control actually goes.

Nine roofers is a leaf on a tree with 700 leaves. The crumb is how a resident gets back up one level to the other home services rather than out to Nearby and in again.

First and last survive, the middle collapses to a control that expands. Truncating the last crumb would hide the one thing the resident is looking at.

Today, Calendar, Creations and You get no breadcrumb at all. They are flat, and a crumb reading "Today › Dardanelle lock reopens" invents a hierarchy to describe a tap. The directory is the only genuinely nested thing in the product, so it is the only place that earns one.

Navy dark, the only navy-dark overlay in the product. A resident who has never built anything will never once see this colour full width.

Two audiences, one app, and this is where that promise is actually kept. A resident who never writes a line of code should be able to use Town Square for a year and never encounter a manifest, a review queue or an MCP token. The separation is enforced by what mounts, not by what is styled quietly, and the visual distance is a second line of defence so that a builder screenshot is never mistaken for the resident product.

When a scrape fails, the API serves the last good screen rather than an error, which is right: a resident opening this at 6am wants the town, not a stack trace. But that policy quietly turns every failure into a lie unless something on the page says how old the answer is. The stale line is gold, not brick. Brick is the one alarm register and it is reserved for an actual emergency, which a late calendar scrape is not. Spending it here is how it stops meaning anything the morning the river is up.
