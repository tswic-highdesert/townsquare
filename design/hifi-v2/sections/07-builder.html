Front door, the honest prerequisite the one card that is allowed to talk someone out of it

You will need an AI tool of your own

Town Square does not write apps for you. There is no chat box here. You bring a tool you already have, it does the writing, and the cost of that writing is yours, not the town's. That is why this is free to host.

  • Claude Code, in a terminal. What we build against, and the smoothest path.
  • Claude Desktop or anything else that speaks MCP. Works, with a little more setup.
  • A phone alone is not enough yet. You need a computer you can run a command on.

You do not need to know JavaScript. You do need to be willing to read what your tool wrote, because you are the one submitting it and your name goes on it.

The temptation on this page is to write anyone in town can make an app, because it is the sentence the thesis wants to be true. It is not true today. What is true is anyone with an AI subscription and a laptop, and a builder who discovers the gap after signing up is a builder who does not come back. So the hero promises a specific, local, buildable thing, the prerequisite card is allowed to say no, and the tone stays flat and unhurried rather than encouraging. Warmth is earned later, at the first publish, where it costs nobody anything.

This whole section lives behind one link in the site footer and one card in Settings. Nothing in the resident tab bar points here, no banner suggests it, and a resident who reads the paper and checks the weekend never sees a token, a manifest, or the word MCP. The build layer is where the value compounds, but it is not where most people live, and cluttering the reading path to advertise it would trade the many for the few.

Code block, a file filename header, line numbers, copy; light because you read it like a document

The bytes never travel through the model. The agent declares a path, a sha256 and a length for every file, gets a one-time ticket, and one shell command moves the actual bytes. A file in the upload that was not in the inventory is rejected, which is what turns "everything is vendored" from a promise into a check.

Two code treatments, on purpose. A file is light, titled, numbered and copyable, because you read it, quote a line of it to someone, and paste it into an editor. A terminal is dark with a prompt glyph and no line numbers, because line 7 of a transcript is not a thing anyone refers to. Syntax colour is the same four registers everywhere: navy for the words the language owns, terracotta for anything quoted, sage for bare values, muted ink for comments. Four is enough to read structure and few enough that a code block never out-shouts the page it sits on.

Permission row the machine value and its consequence sit on one line, so declaring is never abstract

What this creation may reach

A reviewer decides from this block alone, usually in under a minute. Everything not declared here is refused at runtime even if your code tries.

"identity": "handle"

Your app can ask who is signed in and gets back a handle and whether they are verified. Never an email, never a real name, never a location.

"read": ["flock_camera"]

Your app can list every camera anyone in town has recorded, including ones added by other creations. @oldpost defined this type in March and 340 rows already exist.

"write": ["flock_camera"]

Your app can add and edit cameras, and every change is stamped with the resident who made it and with your creation. This is the one a reviewer will ask you about, so say in your note why it needs it.

"storage": false

Off. Turn it on only if you save something per person, like a filter they picked. 64 KB each, private to them, invisible to every other creation.

"device": []

Not available yet. Geolocation and camera access land in a later SDK. The field exists now so a map has somewhere to ask later without breaking every manifest written before it.

Network allowlist entry a hostname, and underneath it the exact policy line a human will approve
tile.openstreetmap.org map tiles
What the reviewer will see, and what the browser will enforce
img-src     'self' data: tile.openstreetmap.orgconnect-src 'self' tile.openstreetmap.orgscript-src  'self'  // never yours to change

Declared hosts reach four directives and no more: connect-src, img-src, media-src, font-src. script-src stays 'self' no matter what you write here, which is the mechanism that makes vendoring real rather than a rule nobody checks.

Images are in that list on purpose. Lock down fetch and leave images open and new Image().src = 'https://…?' + secret still walks data out the door without ever needing a reply.

No conflict. Russellville has 6 record types and none is named trail_condition.

The permissions block is the reviewer's entire job, so the authoring surface has to slow a builder down at exactly the moment their AI tool has offered to move fast. Three choices do that. The consequence sits beside the value, in the second person, so nobody declares write without reading what write means. The compiled CSP is shown while you type, because the thing being approved is a policy string and hiding it until review means the builder is surprised twice. And defines carries a plainly worded permanence warning, because additive-only forever is genuinely unusual and a builder who learns it from a rejection learned it too late.

Pass the type as a plain string: records.list('flock_camera'). If you need two types, write two calls and declare both.

"storage": true is declared but storage.get and storage.set are never called anywhere in the bundle.

Set it to false. This will not block you, but a permissions block full of things you do not use is a slower review, and AI tools ask for storage out of habit.

await records.create(type, data) needs write

Adds one record of a type your manifest declares under permissions.write. Attribution is automatic: the acting resident and your creation are both stamped on the row, and you cannot set either, which is precisely why neither can be forged.

Parameters
type string literal
The record type, written out as a quoted string. A variable here is a validation error, because a reviewer cannot see what an app writes if the source does not say it.
data object
Must match the type's schema. Anything extra is rejected rather than ignored.
Returns
{ id: 'rec_8fJ2q', version: 1, created_at: '2026-08-05T14:02:11Z' }
Example
Throws
  • not_verifiedSigned in, but neighbours have not vouched yet. Not retryable.
  • unauthenticatedSigned out. The common case, so handle it first.
  • permission_deniedThe type is not in your manifest's write list.
  • invalid_recordPayload does not match the schema.
  • rate_limitedCarries retry_after. One of only two worth retrying.
